# okf-ai

Open-source инструменты для базы знаний в формате [Open Knowledge Format v0.2](https://github.com/GoogleCloudPlatform/open-knowledge-format):
Markdown-файлы в Git с YAML-шапкой, которые одинаково удобно читать человеку и ИИ-агенту.

Что уже есть (первый спринт):

- `okf validate` — проверяет бандл по правилам этапа 1 ([спека](etc/spec/cli-validator.md));
- `okf agents` — собирает `AGENTS.md`, компактное оглавление-роутер для агентов;
- `okf stale` — находит документы, которые могли устареть после изменения кода;
- [GitHub Action](.github/workflows/okf.yml) — запускает validate и stale на каждом pull request.

Концепция и планы — в [брифе](etc/docs/BRIEF.md).

## Установка

Нужен Python 3.10+ и Git.

```bash
git clone https://github.com/Smoooky/okf-ai.git
cd okf-ai
pip install -e ".[test]"
```

На Windows вместо `pip` и `python` — `py -3.12 -m pip` и `py -3.12`. Если папка `Scripts` не в `PATH`,
команда `okf` не найдётся; тогда запускайте `py -3.12 -m okf ...` — это то же самое.

Тесты:

```bash
python -m pytest
```

## Команды

### `okf validate <bundle>`

Проверяет все `.md` файлы бандла и печатает по строке на проблему:

```text
[LEVEL] file_path: field_name: message
```

```text
[ERROR] examples/broken/agent_overconfident.md: trust.confidence: Value 1.0 is reserved for human-verified knowledge; a document generated by "agent" must have confidence below 1.0
[ERROR] examples/broken/wrong_type.md: type: Value "Endpoint" is not in the allowed type dictionary (did you mean "API Endpoint"?)
[WARNING] examples/broken/broken_link.md: link: Broken link to concepts/missing_file.md
```

- Код выхода `1`, если есть хоть один `ERROR`; `0`, если только `WARNING` или ничего.
- Пути печатаются относительно текущей папки. Итоговая строка (`okf validate: 11 files, 12 errors, 2 warnings`)
  уходит в stderr, чтобы stdout оставался строго в формате выше.
- `--format github` печатает те же проблемы как команды GitHub Actions — они становятся аннотациями в PR.

Что проверяется:

| Правило | Уровень |
|---|---|
| файл знаний начинается с YAML-шапки `---` и она закрыта | ERROR |
| шапка — валидный YAML и словарь `ключ: значение`, а не список или текст | ERROR |
| у служебных `index.md` и `log.md` в корне бандла **нет** шапки | ERROR |
| `type` есть, не пустой и входит в словарь (см. ниже) | ERROR |
| `tags`, если есть, — список строк | ERROR |
| `provenance.sources` — непустой список строк | ERROR |
| `trust.confidence` — число от 0.0 до 1.0 | ERROR |
| при `trust.generated: script` или `agent` — `trust.confidence` меньше 1.0 | ERROR |
| `trust.verified_by` заполнен (всегда, и для агентских документов тоже) | ERROR |
| `freshness.last_reviewed` и `freshness.stale_after` — даты `YYYY-MM-DD` | ERROR |
| `freshness.stale_after` не раньше `freshness.last_reviewed` | ERROR |
| markdown-ссылки ведут на существующие файлы | WARNING |
| на каждый документ ссылается хотя бы один другой файл бандла (нет «сирот») | WARNING |

### `okf agents <bundle>`

Пишет `<bundle>/AGENTS.md`: короткую инструкцию для агента и таблицу документов —
заголовок, `type`, `tags`, свежесть, доверие и путь. Агент читает только роутер и открывает нужные файлы
по мере надобности, а не весь бандл. Пример — [examples/demo/AGENTS.md](examples/demo/AGENTS.md).

- Свежесть: `fresh until <дата>`, `review due <дата>` (осталось ≤30 дней), `stale since <дата>`;
  если `lifecycle.status` не `stable`, он добавляется впереди (`draft, fresh until ...`).
- `-o PATH` — другой путь, `-o -` — в stdout; `--check` — ничего не пишет, код `1`, если файл устарел;
  `--today YYYY-MM-DD` — посчитать свежесть на другую дату.
- Документы с битой шапкой в роутер не попадают — об этом предупреждение в stderr.

### `okf stale <bundle> [--changed FILE...] [--base REF]`

Сопоставляет изменённые файлы кода с `provenance.sources` и предупреждает, какие документы могли устареть:

```text
[WARNING] examples/demo/auth_flow.md: provenance.sources: Source git://examples/demo/src/auth.py changed; document may be outdated, ask teamlead_ivan to review it
```

- `--changed a.py b.py` — список изменённых файлов, пути от корня репозитория (как в `git diff --name-only`);
  `--changed -` читает их из stdin.
- `--base origin/main` — взять изменения из Git: всё, что поменялось с общего предка с `origin/main`,
  включая незакоммиченные правки отслеживаемых файлов.
- Если документ изменён в том же наборе изменений, что и его код, вместо WARNING будет `[INFO] ... document was updated in the same change`.
- Отдельно, независимо от изменений, помечает документы, у которых `freshness.stale_after` уже прошла.
  `--today YYYY-MM-DD` позволяет «перемотать время».
- Код выхода всегда `0` (это предупреждения), `2` — если не удалось вызвать git.

## Соглашения формата

Эталонная шапка документа:

```yaml
---
type: "Architecture"
tags: [auth, security]
provenance:
  sources:
    - "git://examples/demo/src/auth.py"
trust:
  generated: "human"            # human | script | agent
  verified_by: "teamlead_ivan"
  confidence: 0.95
lifecycle:
  status: "stable"
freshness:
  last_reviewed: "2026-10-19"
  stale_after: "2027-04-19"
timestamp: "2026-10-19T10:00:00Z"
---
```

- **Источники.** Ссылка на код — `git://<путь от корня репозитория>`, например `git://examples/demo/src/auth.py`.
  Можно указать папку (`git://src/billing/`) или маску (`git://src/*.sql`), якорь строк (`#L10-L20`) игнорируется.
  Другие источники — URL, `jira://WHL-42` и т.п. — допустимы для validate, но `okf stale` смотрит только на `git://`.
- **`freshness`** — на верхнем уровне шапки, а не внутри `lifecycle`. Если валидатор найдёт `lifecycle.freshness`, он подскажет.
- **Словарь `type`** — ровно эти строки, с учётом регистра и пробелов:
  `Concept`, `Architecture`, `Table`, `Dataset`, `Metric`, `API Endpoint`, `Runbook`, `Playbook`, `Guide`,
  `Reference`, `Policy`, `Service`, `Repository`, `Glossary Term`.
- **Служебные файлы.** `index.md` и `log.md` в корне бандла — обычный Markdown без шапки.
  `AGENTS.md` генерируется командой `okf agents`, не проверяется и не считается входящей ссылкой при поиске «сирот».
  Папки, начинающиеся с точки, пропускаются.
- **Ссылки.** Относительные пути считаются от файла, пути с `/` — от корня бандла. Внешние ссылки,
  якоря и код в `` ` `` и ```` ``` ```` не проверяются.

## GitHub Action

[`.github/workflows/okf.yml`](.github/workflows/okf.yml) на каждый pull request и push в `main`:

1. гоняет pytest;
2. `okf validate` по бандлу из переменной `OKF_BUNDLE` (сейчас `examples/demo`) — ошибки валят проверку;
3. `okf stale --base origin/<базовая ветка>` — предупреждает о документах, чей код поменялся в PR;
4. пишет отчёт в лог, в job summary и аннотациями на файлы; в PR из этого же репозитория — обновляемым комментарием.

Чтобы подключить к своему репозиторию, скопируйте файл и поменяйте `OKF_BUNDLE`.

## Демо за 2 минуты

В репозитории два бандла: [`examples/demo`](examples/demo) — база знаний выдуманного сервиса аренды самокатов
Wheelo (9 документов, `index.md`, `log.md`, код в `src/`), и [`examples/broken`](examples/broken) —
по файлу на каждую ошибку. В [`examples/demo-pr`](examples/demo-pr) лежат заготовки изменений для демо.

**0. Показать, что валидатор ловит** (10 секунд):

```bash
okf validate examples/broken
```

**1. PR меняет код авторизации.** Refresh-токен теперь живёт 7 дней вместо 30, блокировка — после 3 попыток вместо 5:

```bash
git switch -c demo/auth-ttl
cp examples/demo-pr/auth.py examples/demo/src/auth.py
okf stale examples/demo --base main
```

```text
[WARNING] examples/demo/auth_flow.md: provenance.sources: Source git://examples/demo/src/auth.py changed; document may be outdated, ask teamlead_ivan to review it
```

В GitHub то же самое видно в PR: аннотация на `auth_flow.md`, отчёт в summary и комментарий.

**2. ИИ-агент обновляет документ, но ставит себе полное доверие:**

```bash
cp examples/demo-pr/auth_flow.md examples/demo/auth_flow.md
okf validate examples/demo
```

```text
[ERROR] examples/demo/auth_flow.md: trust.confidence: Value 1.0 is reserved for human-verified knowledge; a document generated by "agent" must have confidence below 1.0
```

Код выхода `1` — в PR проверка красная.

**3. Исправляем — всё зелёное:**

```bash
sed -i 's/confidence: 1.0/confidence: 0.8/' examples/demo/auth_flow.md
okf validate examples/demo && okf stale examples/demo --base main
okf agents examples/demo
```

`validate` молчит и выходит с `0`, `stale` пишет `[INFO] ... document was updated in the same change`,
а `AGENTS.md` теперь говорит агенту, что документ написан агентом с доверием 0.8.

Чтобы показать то же на GitHub, после каждого шага делайте `git commit -am "..." && git push`
(в первый раз — `git push -u origin demo/auth-ttl` и откройте PR): Action перезапускается на каждый push.

Вернуть всё как было: `git checkout -- examples/demo && git switch main && git branch -D demo/auth-ttl`.

Бонус — «перемотать время» и увидеть просроченные документы:

```bash
okf stale examples/demo --today 2027-03-01
```

## Структура

```text
src/okf/        пакет: bundle.py (чтение бандла), validate.py, agents.py, stale.py, cli.py
tests/          pytest: по тесту на каждое правило спеки, stale, agents, CLI
examples/       demo, broken, demo-pr
etc/            бриф, спека, конкурентный анализ, интервью-кит
```
