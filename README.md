# okf-ai

Валидатор [Open Knowledge Format v0.2](https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/main/SPEC.md)
плюс строгий профиль okf-ai. База знаний — Markdown-файлы в Git с YAML-шапкой, которые одинаково удобно
читать человеку и ИИ-агенту.

Что уже есть (первый спринт):

- `okf validate` — соответствие OKF v0.2; с `--strict` — ещё и правила команды ([спека v2](etc/spec/cli-validator-v2.md));
- `okf agents` — собирает `AGENTS.md`, компактное оглавление-роутер для агентов;
- `okf stale` — находит документы, которые могли устареть после изменения кода;
- [GitHub Action](.github/workflows/okf.yml) — validate и stale на каждом pull request.

Концепция и планы — в [брифе](etc/docs/BRIEF.md).

## Установка

Нужен Python 3.10+ и Git.

```bash
git clone https://github.com/Smoooky/okf-ai.git
cd okf-ai
pip install -e ".[test]"
```

На Windows вместо `pip` и `python` — `py -3.12 -m pip` и `py -3.12`. Если папка `Scripts` не в `PATH`,
команда `okf` не найдётся; тогда запускайте `py -3.12 -m okf ...` — это то же самое.

Тесты:

```bash
python -m pytest
```

## Команды

### `okf validate <bundle> [--strict]`

Печатает по строке на проблему:

```text
[LEVEL] file_path: field_name: message
```

```text
[ERROR] examples/broken/agent_unreviewed_stable.md: verified: Document generated by "wheelo-docs-agent/1.4" is status: stable without human review; add a human:<id> entry to verified or set status: draft
[ERROR] examples/broken/bad_fields.md: stale_after: Value "2027-10-19" must be an ISO 8601 datetime with a UTC offset, e.g. 2026-06-30T14:00:00Z
[WARNING] examples/broken/broken_link.md: link: Broken link to /concepts/missing_file.md
```

- Код выхода `1`, если есть хоть один `ERROR`; `0`, если только `WARNING` или ничего.
- Пути печатаются относительно текущей папки. Итоговая строка (`okf validate (strict): 13 files, 19 errors, 4 warnings`)
  уходит в stderr, чтобы stdout оставался строго в формате выше.
- `--format github` печатает те же проблемы как команды GitHub Actions — они становятся аннотациями в PR.

**По умолчанию — OKF v0.2.** Обязателен только `type`; незнакомые типы и лишние ключи — не ошибка.
Официальные примеры бандлов проходят без ошибок (один лежит в [tests/fixtures](tests/fixtures/okf-official)).

| Правило | Уровень |
|---|---|
| у документа есть YAML-шапка, она парсится и это словарь | ERROR |
| `type` есть, непустая строка | ERROR |
| `sources` — список записей, у каждой есть `resource` | ERROR |
| `generated` содержит `by`; у каждой записи `verified` есть `by` и `at` | ERROR |
| акторы — `human:<id>`, `process:<id>` или `<producer>/<version>` | ERROR |
| `status` — `draft`, `stable` или `deprecated` | ERROR |
| `stale_after`, все `at`, `last_modified`, `usage_window` — ISO 8601 с UTC-смещением | ERROR |
| `Attested Computation` содержит `runtime` | ERROR |
| у `index.md` нет шапки (корневой может содержать только `okf_version`) | ERROR |
| `tags` — YAML-список строк | WARNING |
| даты в заголовках `log.md` — `YYYY-MM-DD` | WARNING |
| markdown-ссылки ведут на существующие файлы | WARNING |

**`--strict` — правила okf-ai** поверх OKF:

| Правило | Уровень |
|---|---|
| `sources` непустой | ERROR |
| `verified` есть | ERROR |
| `stale_after` есть и не раньше последней `verified[].at` | ERROR |
| документ, который написал не человек (`generated.by` — агент или процесс), может быть `stable`, только если в `verified` есть `human:` | ERROR |
| `tags` — YAML-список строк | ERROR |
| у `log.md` нет шапки | ERROR |
| `type` из [словаря команды](etc/spec/cli-validator-v2.md#приложение-2-словарь-type-для---strict) | WARNING |
| на документ ссылается хотя бы один другой файл (нет «сирот») | WARNING |

#### Поля первой версии спеки → OKF v0.2

| Было в `cli-validator.md` | Стало |
|---|---|
| `provenance.sources: ["git://src/auth.py"]` | `sources: [{resource: /src/auth.py}]` |
| `trust.generated: human / script / agent` | `generated: {by: human:<id> / process:<id> / <agent>/<version>, at: ...}` |
| `trust.verified_by: ivan` | `verified: [{by: human:ivan, at: 2026-10-19T10:00:00Z}]` |
| `trust.confidence` | нет: уровень доверия выводится из `verified` — unverified, machine-confirmed, human-reviewed |
| агент + `confidence: 1.0` → ошибка | агент + `status: stable` без `human:` в `verified` → ошибка в `--strict` |
| `lifecycle.status` | `status` |
| `freshness.last_reviewed` | последняя `verified[].at` |
| `freshness.stale_after: 2027-04-19` | `stale_after: 2027-04-19T00:00:00Z` |
| `timestamp` | `generated.at` |

Старые поля для OKF — просто лишние ключи, поэтому без `--strict` ошибок не будет;
`--strict` подскажет, на что их заменить.

### `okf agents <bundle>`

Пишет `<bundle>/AGENTS.md`: короткую инструкцию для агента и таблицу документов —
заголовок с описанием, `type`, `tags`, свежесть, уровень доверия и путь. Агент читает только роутер
и открывает нужные файлы по мере надобности. Пример — [examples/demo/AGENTS.md](examples/demo/AGENTS.md).

- У самого `AGENTS.md` есть шапка (`type: Agent Router`), чтобы бандл оставался валидным OKF и для чужих инструментов.
- Свежесть: `fresh until <дата>`, `review due <дата>` (осталось ≤30 дней), `stale since <дата>`, `no stale_after`;
  `draft` и `deprecated` указываются впереди.
- Доверие: `human-reviewed`, `machine-confirmed` или `unverified` и кто написал (`generated.by`).
- `-o PATH` — другой путь, `-o -` — в stdout; `--check` — ничего не пишет, код `1`, если файл устарел;
  `--now 2026-10-22` — посчитать свежесть на другой момент.

### `okf stale <bundle> [--changed FILE...] [--base REF]`

Сопоставляет изменённые файлы с `sources[].resource` и предупреждает, какие документы могли устареть:

```text
[WARNING] examples/demo/auth_flow.md: sources: Source /src/auth.py changed (examples/demo/src/auth.py); document may be outdated, ask human:teamlead_ivan to review it
```

- `--changed a.py b.py` — пути от корня репозитория (как в `git diff --name-only`); `--changed -` — из stdin.
- `--base origin/main` — взять изменения из Git: всё, что поменялось с общего предка, включая незакоммиченные правки.
- Как читается `resource`: `/path` — от корня бандла; `./path`, `../path` — от файла документа;
  `path` — от файла или от корня бандла (так пишут официальные примеры);
  `https://github.com/<owner>/<repo>/blob/<ref>/<path>` — файл `<path>` этого репозитория.
  Папка ловит изменения внутри неё, маска (`/src/*.sql`) — подходящие файлы; другие URL и описания областей игнорируются.
- Если документ изменён вместе с источником, вместо WARNING — `[INFO] ... document was updated in the same change`.
- Отдельно помечает документы, у которых наступил `stale_after` (`now >= stale_after`).
  `--now 2027-03-01` позволяет «перемотать время».
- Код выхода всегда `0`, `2` — если не удалось вызвать git.

## Соглашения

- `index.md` и `log.md` зарезервированы на любом уровне (§3.1): это не документы, `type` им не нужен.
- `AGENTS.md` в корне бандла — сгенерированный роутер: валидатор его пропускает, его ссылки не спасают от «сирот».
- Папки, начинающиеся с точки, пропускаются.
- Ссылки: `/path` — от корня бандла (рекомендует OKF), иначе от файла. Внешние ссылки, якоря,
  сноски `[^id]` и код не проверяются.

## GitHub Action

[`.github/workflows/okf.yml`](.github/workflows/okf.yml) на каждый pull request и push в `main`:

1. гоняет pytest;
2. `okf validate $OKF_BUNDLE $OKF_VALIDATE_ARGS` (сейчас `examples/demo --strict`) — ошибки валят проверку;
3. `okf stale --base origin/<базовая ветка>` — предупреждает о документах, чей код поменялся в PR;
4. пишет отчёт в лог, в job summary и аннотациями на файлы; в PR из этого же репозитория — обновляемым комментарием.

Чтобы подключить к своему репозиторию, скопируйте файл и поменяйте `OKF_BUNDLE`; для чистой проверки OKF
оставьте `OKF_VALIDATE_ARGS` пустым.

## Демо за 2 минуты

В репозитории:
- [`examples/demo`](examples/demo) — база знаний выдуманного сервиса аренды самокатов Wheelo: 9 документов, `index.md`, `log.md`, код в `src/`;
- [`examples/broken`](examples/broken) — по файлу на каждую ошибку;
- [`examples/demo-pr`](examples/demo-pr) — заготовки изменений для демо.

**0. Что ловит валидатор** (10 секунд):

```bash
okf validate examples/broken            # OKF v0.2: 11 ошибок
okf validate examples/broken --strict   # правила okf-ai: 19 ошибок
```

**1. PR меняет код авторизации.** Refresh-токен теперь живёт 7 дней вместо 30, блокировка — после 3 попыток вместо 5:

```bash
git switch -c demo/auth-ttl
cp examples/demo-pr/auth.py examples/demo/src/auth.py
okf stale examples/demo --base main
```

```text
[WARNING] examples/demo/auth_flow.md: sources: Source /src/auth.py changed (examples/demo/src/auth.py); document may be outdated, ask human:teamlead_ivan to review it
```

В GitHub то же видно в PR: аннотация на `auth_flow.md`, отчёт в summary и комментарий.

**2. ИИ-агент обновляет документ и сразу помечает его `stable`.** Проверял его только CI-процесс, человек — нет:

```bash
cp examples/demo-pr/auth_flow.md examples/demo/auth_flow.md
okf validate examples/demo --strict
```

```text
[ERROR] examples/demo/auth_flow.md: verified: Document generated by "wheelo-docs-agent/1.4" is status: stable without human review; add a human:<id> entry to verified or set status: draft
```

Код выхода `1` — в PR проверка красная.

**3. Тимлид проверяет документ и подтверждает — всё зелёное:**

```bash
sed -i 's/by: process:okf-ci/by: human:teamlead_ivan/' examples/demo/auth_flow.md
okf validate examples/demo --strict && okf stale examples/demo --base main
okf agents examples/demo
```

`validate` молчит и выходит с `0`, `stale` пишет `[INFO] ... document was updated in the same change`,
а в `AGENTS.md` документ теперь `human-reviewed, written by wheelo-docs-agent/1.4`.
Другой честный выход — `status: draft`: тогда агенты видят, что документ ещё не проверен.

Чтобы показать то же на GitHub, после каждого шага делайте `git commit -am "..." && git push`
(в первый раз — `git push -u origin demo/auth-ttl` и откройте PR): Action перезапускается на каждый push.

Вернуть всё как было: `git checkout -- examples/demo && git switch main && git branch -D demo/auth-ttl`.

Бонус — «перемотать время» и увидеть просроченные документы:

```bash
okf stale examples/demo --now 2027-03-01
```
