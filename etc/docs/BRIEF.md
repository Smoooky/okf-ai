# Концепция и Бриф Продукта: Автоматически обновляемая база знаний в формате Open Knowledge Format (OKF v0.2)

**Единый источник правды для людей и ИИ-агентов без накладных расходов на инфраструктуру.**

**Репозиторий проекта:** https://github.com/Smoooky/okf-ai

---

## 1. Проблема и контекст

* **Разрыв между человеком и ИИ:** Документация в Confluence и Notion пишется для людей и быстро устаревает. Векторные базы данных (RAG) непрозрачны для человека, требуют сложных пайплайнов и дороги в поддержке.
* **Галлюцинации и раздувание контекста (Token bloat):** AI-агенты тратят тысячи токенов на сканирование «мусорных» файлов без понимания их свежести и источника. При классическом RAG-подходе агент часто получает устаревший или избыточный кусок текста.
* **Отсутствие стандарта жизненного цикла знаний:** Существующие конвенции вроде `AGENTS.md` или `CLAUDE.md` задают лишь правила поведения конкретного агента в репозитории, но не стандартизируют структуру, метаданные и актуализацию самих предметных знаний компании.

---

## 2. Наше решение (Value Proposition)

Мы строим **open-source** систему, объединяющую архитектуру LLM-Wiki Андрея Карпатого и открытую спецификацию Google Cloud OKF. Наш продукт автоматически превращает разрозненную документацию компании в стандартизированные, легковесные **Knowledge Bundles** (наборы знаний), которые одинаково удобно читать человеку в Git/Markdown-редакторе и сканировать AI-агенту. Продукт и все экстракторы бесплатны; монетизация — только платная поддержка.

### Ключевые архитектурные принципы:
* **Формат файлов:** Набор Markdown-файлов с обязательным структурированным YAML Frontmatter (тип, теги, происхождение информации, уровень доверия и жизненный цикл).
* **Навигация (Lazy Loading):** Файл `AGENTS.md` служит компактным маршрутизатором-оглавлением (роутером), а не тяжелой энциклопедией. Агент загружает узкоспециализированные файлы только по мере необходимости, экономя контекстное окно и токены.
* **Ключевая ценность (Freshness Engine):** Непрерывная фоновая актуализация данных на основе изменений в коде, тикетах таск-трекеров и коммуникациях команды.

## 3. Сравнительный анализ архитектуры баз знаний

| Критерий | Традиционные базы (Notion, Confluence) | Обычный RAG (Векторные БД) | **Наш продукт (OKF v0.2 Bundle)** |
| :--- | :--- | :--- | :--- |
| **Для кого предназначен** | Исключительно для людей | Исключительно для ИИ-моделей | **И для людей, и для ИИ-агентов** |
| **Потребление памяти / контекста ИИ** | Недоступно напрямую (нужен парсинг) | Огромное (агент «читает» лишний контекст) | **Минимальное (Lazy-loading по запросу через роутер)** |
| **Доверие к данным (Trust)** | Субъективное (кто последний правил?) | Отсутствует (ИИ может взять устаревший кусок) | **Вшито в метаданные** (`sources`, `generated`, `verified`, `stale_after` — поля OKF v0.2) |
| **Инфраструктура** | Проприетарное облако, платные подписки | Тяжелые векторные БД, серверы, эмбеддинг-пайплайны | **Простые файлы в Git** (Zero Infrastructure) |

## 4. Разделение продукта: бесплатный продукт и платная поддержка

> **Статус (22.10.2026).** Модель денег — гипотеза. Расчёт в [маркет-рисёрче](research/market-research/2026-10-22_17-16_okf-ai-market-research-result.md): «платно только поддержка» в первые 1–2 года даёт почти ноль (поддержку покупают те, у кого продукт уже в проде), Open Core (платная автоматизация) выглядит сильнее, но тоже не проверен. В PDF-брифе от 18.10 была версия Open Core + SaaS — команде нужно выбрать одну.

Стратегия: **весь продукт и все экстракторы — бесплатно и открыто; платно — только поддержка**. Это снижает барьер входа и отдаёт дистрибуцию сообществу. Продаём не код, а ответственность: SLA, именного инженера и помощь с security review.

**Граница стоимости.** Продукт разворачивается self-hosted: инфраструктуру и вызовы LLM оплачивает компания. Мы не продаём код, экстракторы или подписку — только поддержку.

```
БЕСПЛАТНО / OPEN SOURCE
├── CLI Валидатор схемы OKF v0.2
├── Bundler & Scaffold, Viewer
├── Локальный парсинг Git-истории (git blame / log)
├── Экстракторы: Git, wiki, Notion, Confluence, Jira, Slack (сделан Git; Confluence и Jira — в работе через интерфейс коннекторов; Notion и Slack — позже)
└── GitHub Action и фоновый ИИ-апдейтер
│
▼
ПЛАТНО — ТОЛЬКО ПОДДЕРЖКА
├── SLA: время реакции и время решения
├── Именной инженер и приоритетные фиксы
├── Помощь с security review и внедрением
└── Контракт на 3 или 12 месяцев
```
### 🛠 Open Source (Ядро для привлечения разработчиков и комьюнити)
Открытая часть является самодостаточным CLI-инструментом для инженеров:
* **CLI Linter / Валидатор:** Утилита, которая проверяет бандл на строгое соответствие схеме OKF v0.2 (валидность YAML frontmatter, отсутствие битых Markdown-ссылок, заполненность обязательных полей вроде `type`).
* **Bundler & Scaffold:** Команда вида `okf init`, которая генерирует каркас `AGENTS.md`, базовую структуру папок и шаблоны сущностей.
* **Локальный парсер Git:** CLI-скрипт, который пробегается по коммитам, вытаскивает авторов (`provenance`) и дату изменения файла для автоматического заполнения базовых полей `freshness`.
* **Viewer:** Локальный инструмент для рендеринга статического HTML или графа связей между файлами знаний, чтобы менеджеры могли читать их в обычном браузере.

### 📦 Возможности продукта (бесплатно)
Ценность продукта — **«Поставил и забыл»**: база знаний живёт сама по себе, без отвлечения инженеров от написания фич. Все перечисленные ниже возможности входят в бесплатную open-source версию.
* **Continuous Ingestion (Внешний контекст):** Подключение к экосистеме компании через Webhooks (Notion API, Confluence, Jira, Slack). Закрепленное сообщение в Slack-канале или закрытый эпик мгновенно отправляют триггер на актуализацию.
* **Background AI-Updater (Фоновый актуализатор):** ИИ-агенты перехватывают коммиты разработчиков, анализируют измененный код, сопоставляют его с нужными файлами в базе знаний (`_architecture.md`, `_api.md`), переписывают их и автоматически создают Pull Request с обновлением.
* **Управление жизненным циклом (Human-in-the-Loop):** Система отслеживает `stale_after` и последнюю дату в `verified`. Если документ долго не обновлялся, а связанный код изменился, система отправляет интерактивное уведомление в Slack/Teams ответственным сотрудникам (из поля `verified[].by`): *«Подтверди актуальность регламента в 1 клик»*.
* **Shadow-Testing баз знаний (Agent CI/CD):** Перед мержем Pull Request система симулирует работу локального ИИ-агента (например, Claude Code) на наборе критических вопросов компании, чтобы проверить, находит ли он нужные файлы и не выдает ли устаревшие данные.

### 🛡 Платная поддержка
Платный продукт — не отдельная версия, а контракт поддержки. Что входит:
* **SLA:** фиксированное время реакции и решения, рабочие часы и каналы.
* **Именной инженер:** конкретный человек, а не очередь в community.
* **Приоритетные фиксы:** исправления проблем, которые блокируют работу.
* **Помощь с security review:** документация, ответы на вопросы безопасности, содействие при внедрении.
* **Сопровождение экстракторов:** обновления API внешних систем (Confluence, Jira, Notion, Slack) берёт на себя команда.

**Почему это честная граница.** Экстрактор легко скопировать; ответственность — нет. Компания платит за то, что когда извлечение знаний сломается, есть кому позвонить и есть срок.

**Главный риск.** Поддержку покупают только после того, как продукт уже стоит в проде: сначала нужно реальное использование, потом страх поломки, потом готовность платить. Это проверяется в интервью и пилотами, а не предполагается.

## 5. Сценарий автоматического обновления (User Story)

1. Разработчик меняет логику авторизации пользователей в коде проекта.
2. Система (бесплатный open-source GitHub App) перехватывает коммит и сопоставляет измененные модули с файлом `auth_flow.md` в OKF-бандле.
3. ИИ-агент на сервере берет старый `auth_flow.md` и диффы из Git, генерирует обновленный текст и записывает в YAML `generated: {by: <агент>, at: <сейчас>}` без новой записи в `verified` — документ становится «сгенерирован, не подтверждён», пока человек его не проверит (в OKF уровень доверия выводится из `verified`, отдельного поля `confidence` нет).
4. Продукт автоматически открывает Pull Request в репозиторий с заголовком: `[OKF-Update] Актуализация документации по авторизации`.
5. Тимлид ревьюит код, видит аккуратный параллельный PR с документацией и нажимает `Merge`. **База знаний всегда актуальна для людей и внешних ИИ-агентов.**

## 7. Roadmap первого спринта (MVP)

1. **Разработка CLI-валидатора (Python / Go):** Парсинг структуры Markdown-файлов, валидация полей YAML Frontmatter на соответствие официальной схеме v0.2.
2. **Скрипт автоматической сборки `AGENTS.md`:** Локальная утилита, сканирующая директорию проекта и собирающая компактное оглавление-маршрутизатор.
3. **Демонстрационный пайплайн автообновления:** Простой GitHub Action, который проверяет файлы в PR, сопоставляет их с базой знаний и выводит предупреждение/предложение об устаревании связанного `.md` файла.
