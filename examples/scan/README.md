## Как выбирали

- Поиск GitHub по коду: `filename:AGENTS.md`, затем `filename:CLAUDE.md`, через `gh api search/code`.
- Оставлены публичные репозитории, не форки и не архивные, с push не старше 3 месяцев.
- Поиск сортирует по релевантности, так что это не случайная выборка всех репозиториев с инструкциями.

## Как читать честно

- **«Перепроверить» здесь не значит «устарело».** В этих репозиториях никто не пользуется `okf verify`. Поэтому пометка означает: файл, который упоминает раздел, менялся после последней правки раздела. Это повод перечитать, а не доказанное расхождение.
- **Точность связей ещё не измерена.** Её даёт ручная разметка `label.csv`. Пока её нет, на слайде цифра X% говорит о найденных пометках, а не о подтверждённом отставании.
- **Первый прогон по тем же коммитам показал больше:** 57% репозиториев со «сломано» и 73% с находками. Разбор показал ложные срабатывания, они исправлены (коммит `39e1113`):
  - сокращённые пути вроде `model/time.ts` вместо `src/model/time.ts`;
  - `n/a` и `pid/tid` в коде, принятые за пути;
  - чужие AGENTS.md в `vendor/`;
  - правки `package.json` при обновлении зависимостей;
  - на Windows 20 клонов падали с «Filename too long».

## Разметка и точность

1. Открыть `label.csv` (Excel или Google Sheets; файл в UTF-8 с BOM). В колонке `url` — ссылка на строку в GitHub.
2. В `correct` написать **да**, если раздел действительно ссылается на этот файл или команду; **нет**, если это не связь (пример, файл, который только предлагают создать, слово вместо пути); **неясно** — если трудно сказать. В `comment` — почему.
3. Посчитать:

```bash
okf scan --score examples/scan/label.csv
```

Порог из PRD: точность ≥80% — связи находятся автоматически; <60% — нужна ручная разметка источников.

## Повторить

```bash
okf scan --repos examples/scan/repos.pinned.txt --out report --now 2026-10-22T16:27:36Z --seed 42
```

Около 5 минут на 49 репозиториев при 4 параллельных клонах. Клоны создаются во временной папке и удаляются после.
