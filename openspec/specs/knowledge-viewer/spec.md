# Knowledge Viewer Specification

## Purpose
Страницы для людей: `okf trust --html FILE` сохраняет карту доверия одной страницей, а `okf view` собирает статический сайт базы знаний OKF с уровнями доверия, навигацией и графом связей. Обе страницы в одном оформлении, открываются офлайн — из артефакта CI или с ноутбука — и показывают уровень доверия так, чтобы его нельзя было не заметить.

## Requirements

### Requirement: Страница карты доверия
С `--html FILE` команда `okf trust` SHALL дополнительно к обычному выводу записывать в `FILE` страницу с теми же единицами, что попали в вывод (с `--since` — только задетые изменением), и печатать в stderr `okf trust: wrote FILE`.

#### Scenario: Страница рядом с выводом
- GIVEN репозиторий с инструкциями и базой знаний
- WHEN запускается `okf trust --html report.html`
- THEN строки карты печатаются как обычно, создан `report.html`, в stderr `okf trust: wrote report.html`, код выхода 0

### Requirement: Офлайн и без внешних зависимостей
Страницы `okf trust --html` и `okf view` MUST NOT загружать скрипты, стили, картинки, шрифты или фреймы из сети: CSS и JS встроены в каждую страницу.

#### Scenario: Проверка страницы
- GIVEN страница карты доверия демо-репозитория или страница сайта
- WHEN её HTML просматривается
- THEN в нём нет `<script src="http…">`, `<link href="http…">`, `<img src="http…">`, `@import` и `url(http…)`, а стили и скрипты стоят внутри `<style>` и `<script>`

### Requirement: Уровень цветом, значком и словом
Каждый уровень доверия на страницах SHALL показываться одновременно цветом, значком и словом: ✓ «подтверждено», ! «перепроверить», ✕ «сломано», ○ «не подтверждено» («подтверждено» объединяет подтверждения человеком и процессом).

#### Scenario: Бейдж уровня
- GIVEN единица «сломано»
- WHEN она показана на странице
- THEN рядом с ней значок `✕` и слово «сломано», а не только красный цвет

### Requirement: Шапка и сводка карты доверия
Страница карты доверия SHALL показывать имя репозитория, ветку и короткий коммит (если это git), дату и время в UTC, фразу `Можно доверять <V> из <N> разделов и документов. Сломано — <B>, перепроверить — <R>, не подтверждено — <U>.`, полосу долей по уровням с текстовой подписью и четыре плитки с числом и долей каждого уровня.

#### Scenario: Демо
- GIVEN демо-репозиторий
- WHEN открывается страница карты доверия
- THEN видны фраза «Можно доверять …», полоса с подписью `сломано: <B>, перепроверить: <R>, …` и плитки четырёх уровней

### Requirement: Фильтры и поиск
Страницы SHALL фильтровать список по уровням (клик по плитке показывает только этот уровень, повторный — все; чипы включают и выключают уровни по отдельности) и по тексту поиска (имя, файл и причина; `/` переводит к поиску, Escape очищает), а если ничего не осталось, показывать «Ничего не найдено. Измените поиск или включите фильтры.».

#### Scenario: Только сломанное
- GIVEN на странице единицы всех уровней
- WHEN нажата плитка «сломано»
- THEN видны только единицы «сломано»
- AND повторное нажатие снова показывает все

#### Scenario: Пустой результат
- GIVEN поиск не совпал ни с одной единицей
- WHEN список отфильтрован
- THEN показано сообщение «Ничего не найдено…»

### Requirement: С чего начать
Страница карты доверия SHALL показывать раздел «С чего начать» с карточками сначала «сломано», затем «перепроверить»: имя единицы, файл и строка, причина простыми словами, таймлайн «проверено <дата> → <что> изменилось <дата>» с разрывом `+<N> дней`, источники и кнопка «Скопировать» с готовой командой.

#### Scenario: Код изменился после подтверждения
- GIVEN `AGENTS.md#Auth` подтверждён `human:ivan` 2026-09-05, `src/auth.py` изменён 2026-10-20
- WHEN открывается страница карты
- THEN в карточке таймлайн `проверено 5 сен 2026` (`human:ivan`) → `код изменился 20 окт 2026` и `+45 дней`
- AND кнопка копирует `okf verify "AGENTS.md#Auth"`

#### Scenario: Сломанная ссылка
- GIVEN раздел ссылается на несуществующий `./scripts/seed_db.sh`
- WHEN открывается страница карты
- THEN карточка стоит в «С чего начать» перед остальными разделами, причина — `Ссылается на то, чего нет: …`, команда — `okf fix`

### Requirement: Команда в карточке
Готовая команда SHALL выбираться по уровню: `okf fix` для «сломано», `okf fix --apply` для переехавшего файла, `okf verify "<unit>"` для остальных «перепроверить» и «не подтверждено», и никакой — для «подтверждено».

#### Scenario: Подтверждённый раздел
- GIVEN единица «подтверждено»
- WHEN она показана на странице
- THEN кнопки с командой у неё нет

### Requirement: Остальные разделы по файлам
Страница карты доверия SHALL показывать единицы, кроме «сломано» и «перепроверить», раскрытыми сворачиваемыми группами по файлам — сначала `AGENTS.md`, затем `CLAUDE.md`, правила Cursor, другие инструкции и папки базы знаний — с числом единиц каждого уровня в заголовке группы, а заметки о ссылках и сгенерированных копиях — разделом «Проверены в другом месте».

#### Scenario: Группа файла
- GIVEN в `AGENTS.md` есть подтверждённые и неподтверждённые разделы
- WHEN открывается страница карты
- THEN в «Остальных разделах» есть раскрытая группа `AGENTS.md`

### Requirement: Ссылки на строки в GitHub
Место единицы SHALL быть ссылкой `https://github.com/<owner>/<repo>/blob/<commit>/<path>#L<line>`, если репозиторий на GitHub (из `GITHUB_REPOSITORY` и `GITHUB_SHA` в Actions, иначе из remote `origin` и HEAD), а иначе — текстом `<path>:<line>`.

#### Scenario: В GitHub Actions
- GIVEN `GITHUB_REPOSITORY=acme/wheelo`, `GITHUB_SHA=abc123`
- WHEN запускается `okf trust --html report.html`
- THEN на странице есть ссылка `https://github.com/acme/wheelo/blob/abc123/AGENTS.md#L7`

#### Scenario: Не на GitHub
- GIVEN у репозитория нет remote `origin` на GitHub и переменных Actions
- WHEN строится страница
- THEN место единицы показано текстом без ссылки

### Requirement: Плашки режима
Страница карты доверия SHALL показывать плашку `Изменение относительно <REF>: задето <N> разделов. Ниже — только они.` при `--since` и плашку о неполной истории git с подсказкой `fetch-depth: 0`, если история shallow.

#### Scenario: Pull request
- GIVEN ветка меняет `src/billing.py`, от которого зависят четыре единицы
- WHEN запускается `okf trust --since main --html report.html`
- THEN на странице `Изменение относительно main: задето 4 раздела`

### Requirement: Светлая и тёмная тема
Страницы SHALL по умолчанию следовать системной теме, а переключатель темы запоминает выбор в хранилище браузера, если оно доступно; без хранилища страница работает и тема просто не запоминается.

#### Scenario: Приватный режим
- GIVEN хранилище браузера недоступно
- WHEN пользователь переключает тему
- THEN тема меняется, ошибок нет, после перезагрузки снова системная

### Requirement: Сайт базы знаний
Команда `okf view [repo] [--out DIR]` SHALL находить бандлы — сам каталог, если в нём корневой `index.md` с `okf_version`, иначе каждый такой каталог внутри, кроме скрытых, `node_modules` и `venv`, — и писать сайт в `DIR` (по умолчанию `site`), а при нескольких бандлах — в `DIR/<имя бандла>/`, печатая в stderr `okf view: <bundle>: <N> documents, open <DIR>/index.html`.

#### Scenario: Демо
- GIVEN `examples/demo` с бандлом `knowledge`
- WHEN запускается `okf view examples/demo --out site`
- THEN в stderr `knowledge: 9 documents`, есть `site/index.html` и `site/graph.html`, код выхода 0

#### Scenario: Нет бандла
- GIVEN в каталоге нет `index.md` с `okf_version`
- WHEN запускается `okf view <dir>`
- THEN код выхода 2 и в stderr `okf view: no OKF bundle (an index.md with okf_version) in <dir>`

#### Scenario: Нет каталога
- GIVEN каталога нет
- WHEN запускается `okf view missing`
- THEN код выхода 2 и в stderr `okf: error: directory not found: missing`

### Requirement: Страницы сайта
Сайт SHALL состоять из главной `index.html`, графа связей `graph.html` и страницы `<путь документа>.html` на каждый документ-концепт бандла, а также на `log.md` и роутер `AGENTS.md`, если они есть; ссылки между документами `.md` ведут на их страницы `.html`.

#### Scenario: Журнал и роутер
- GIVEN в бандле есть `log.md` и `AGENTS.md`
- WHEN собирается сайт
- THEN есть `log.html` и `AGENTS.html`, а в навигации — «Журнал изменений» и «Роутер для агентов»

### Requirement: Навигация сайта
Боковая навигация SHALL повторять разделы `index.md` (заголовок и документы, на которые ссылается его список), а документы без ссылки из `index.md` показывать в группе «Другие документы», с точкой уровня у каждого документа, поиском по названиям, отметкой открытой страницы и выдвижным меню на узком экране.

#### Scenario: Разделы index.md
- GIVEN в `index.md` демо раздел «Архитектура и сервисы» со ссылками на документы
- WHEN открывается любая страница сайта
- THEN в навигации группа «Архитектура и сервисы» с этими документами, у открытого — `aria-current="page"`

### Requirement: Главная сайта
Главная SHALL показывать заголовок из `# …` в `index.md` (иначе `База знаний <папка>`), вступление `index.md`, фразу «Можно доверять <V> из <N> документов», ту же полосу и плитки уровней, таблицу документов (название с описанием и `status`, если он не по умолчанию, тип, свежесть, уровень доверия), отсортированную по уровню, и фильтр по тегам.

#### Scenario: Фильтр по тегу
- GIVEN документы с тегами `billing` и `api`
- WHEN нажат тег `#billing`
- THEN в таблице только документы с этим тегом, повторное нажатие снимает фильтр

### Requirement: Свежесть документа
Свежесть SHALL считаться по `stale_after`: `через <N> дней` (выделено, если осталось 30 дней или меньше), `сегодня`, `просрочен с <дата>` или `без срока`, с датами по-русски вида `22 окт 2026`.

#### Scenario: Срок скоро
- GIVEN сейчас 2026-10-22, `stale_after: 2026-11-01`
- WHEN считается свежесть
- THEN показано `через 9 дней`, выделено как близкий срок

#### Scenario: Срок прошёл
- GIVEN `stale_after: 2026-10-01`
- WHEN считается свежесть
- THEN показано `просрочен с 1 окт 2026`

### Requirement: Страница документа
Страница документа SHALL показывать крошки, название, бейджи `type`, `status` и уровня, описание, текст документа и «паспорт знания»: уровень с причиной, источники (веб-адрес — ссылкой с названием, путь — кодом, с датой `last_modified`), кто сгенерировал, кто и когда подтвердил (или «никем»), свежесть со сроком и теги, а сноска `[^id]` в тексте ведёт на источник с тем же `id`.

#### Scenario: Документ с эпиком в источниках
- GIVEN документ `ride_conversion_metric.md` с источником `https://wheelo.atlassian.net/browse/WHL-42` (`id: definition`) и сноской `[^definition]`
- WHEN открывается его страница
- THEN в паспорте ссылка «Эпик: определение сессии» на этот адрес, и сноска ведёт на него же

### Requirement: Баннер устаревания
Страница документа SHALL показывать баннер «Документ надо перепроверить.» или «Документ сломан.» с причиной простыми словами, если документ на этом уровне, а иначе — баннер «Срок свежести истёк <дата>. Сверьте документ с источниками.», если `stale_after` наступил.

#### Scenario: Код изменился
- GIVEN документ `auth_flow.md` «перепроверить»: `src/auth.py` изменён 2026-10-20 после подтверждения
- WHEN открывается его страница
- THEN баннер «Документ надо перепроверить. Код изменился после подтверждения: `src/auth.py`, 20 окт 2026»
- AND в навигации у документа точка уровня «перепроверить»

#### Scenario: Без истории git
- GIVEN каталог не является репозиторием git
- WHEN собирается сайт
- THEN изменения кода неизвестны, и баннера «надо перепроверить» из-за них нет

### Requirement: Граф связей
Страница `graph.html` SHALL показывать каждый документ узлом с его названием и значком уровня, ссылку между двумя документами — ребром, подсвечивать соседей при наведении, масштабировать колесом и кнопками, сдвигать перетаскиванием, открывать документ по клику и показывать легенду уровней.

#### Scenario: Демо
- GIVEN бандл демо из 9 документов со ссылками между ними
- WHEN открывается `graph.html`
- THEN на графе 9 узлов, рёбра для связанных документов, кнопки масштаба и легенда

### Requirement: Безопасные ссылки в тексте
При переводе Markdown документа в HTML ссылки со схемой, кроме `http`, `https` и `mailto`, MUST NOT становиться ссылками: остаётся только их текст.

#### Scenario: javascript-ссылка
- GIVEN в документе `[bad](javascript:alert(1))`
- WHEN строится страница
- THEN на странице текст `bad` без ссылки и без `javascript:`
