## Why

Сегодня карта доверия знает только один источник правды — git: `sources[].resource` документа OKF считается, только если это путь или ссылка GitHub на файл этого репозитория, а ссылки на Confluence и Jira молча пропускаются. Но в командах знания и решения живут именно там: документ «как устроен биллинг» ссылается на страницу Confluence, а раздел про тарифы — на эпик Jira. Когда страницу переписали или эпик закрыли, документ так же незаметно стареет, как и при изменении кода. Нужен способ подключать такие источники, не переписывая `okf trust` под каждую систему, и способ завести существующие страницы Confluence в базу знаний OKF одной командой.

## What Changes

- Единый интерфейс источника и реестр коннекторов: `okf` выбирает коннектор по виду `resource`; новый коннектор — один файл плюс регистрация. Git становится первым коннектором, его поведение не меняется.
- Коннектор Confluence: распознаёт страницы Cloud (`https://<site>.atlassian.net/wiki/spaces/<KEY>/pages/<id>/...`), Server/Data Center (`.../pages/viewpage.action?pageId=<id>`) и `confluence://<id>`; отдаёт дату последнего изменения и номер версии страницы и текстовый дифф страницы с заданной даты.
- Новая команда `okf import confluence --space KEY [--page ID] --out <bundle>`: пишет страницы пространства (или одну страницу) валидными файлами OKF с `sources` на страницу и `generated: {by: process:okf-import}`.
- Коннектор Jira: распознаёт задачи `https://<host>/browse/KEY-123` и `jira://KEY-123` и отдаёт статус задачи и дату перехода в Done.
- `okf trust` учитывает такие источники: страница изменена после последнего подтверждения или эпик/задача перешли в Done после него — документ «перепроверить».
- Настройка только через переменные окружения: `OKF_CONFLUENCE_URL`, `OKF_JIRA_URL`, `OKF_ATLASSIAN_EMAIL` + `OKF_ATLASSIAN_TOKEN` (Cloud) или `OKF_ATLASSIAN_PAT` (Server/Data Center). Без настройки — ни одного сетевого запроса.
- Надёжность: токены никогда не печатаются; ответы 401/403/404/429 и недоступность сети дают статус источника «неизвестно» с причиной, а не падение; ресурс без настроенного коннектора — `unknown: connector not configured`.

## Capabilities

### New Capabilities
- `source-connectors`: интерфейс и реестр источников, коннекторы git, Confluence и Jira, импорт пространства Confluence в OKF, настройка, сеть и обработка ошибок.

### Modified Capabilities
- `trust-map`: требование «Источники единицы знаний OKF» — ссылки Confluence и Jira в `sources[].resource` становятся источниками через коннекторы, а не пропускаются; статус «неизвестно» не делает документ «сломано» или «перепроверить».

## Impact

- Код: новый модуль источников и коннекторов; `trust.py` и `stale.py` разрешают `resource` через реестр (для путей — git-коннектор, поведение `okf stale` не меняется); новая подкоманда `okf import` в `cli.py`.
- Затрагиваются только `sources[].resource` документов OKF; извлечение путей и команд из инструкций агентов (`okf agents-check`) не меняется.
- Зависимости: цель — без новых обязательных пакетов; коннекторы не нужны тем, кто их не настраивает.
- Тесты: ответы Confluence и Jira — записанные фикстуры; ни один тест не ходит в сеть.
- Документация: раздел о коннекторах в `README.md`, переменные окружения; GitHub Action может передавать их из секретов по желанию.
- Совместимость: без переменных окружения вывод `okf trust`, `okf stale`, `okf validate` совпадает с текущим, кроме заметки `unknown: connector not configured` у ссылок на Confluence и Jira.

## Non-Goals

- Notion: по оценке команды, API не даёт надёжной даты изменения и истории версий.
- Slack и другие мессенджеры как источники знаний.
- Сервер вебхуков и обновления в реальном времени: проверка остаётся запуском команды или Action.
- Облачный сервис okf-ai: всё работает локально или в CI пользователя с его токенами.
